# miniMol — Milestone 2 engineering report

Recorded 1 November 2026 (Asia/Kolkata). **Milestone 2 is implemented and tested.**
The complete two-phone product remains unfinished: production binary framing,
WebRTC, QR pairing, offline/UI integration and physical-device trials follow.

## What works

- Browser-compatible scalar CPU Transformer with row-major matrix multiplication,
  byte and learned-position embeddings, six-head causal self-attention, stable
  softmax, pre-LayerNorm, exact erf GELU, MLP, residuals, final norm and output head.
- Phone 1 loads only `phone1.bin` and owns embeddings/layers 0–2. Phone 2 loads only
  `phone2.bin` and owns layers 3–5/final norm/head. Construction requires a verified
  role-matching shard; no engine exposes all six layers.
- Strict schema/config/ownership/offset/size checks, SHA-256 verification and
  rejection of nonfinite weights. Loading code cannot substitute the peer shard
  or full weights. The existing M1 binaries and golden fixture are unchanged.
- Independent 4,718,592-byte (4.5 MiB) KV caches per role. Every input byte performs
  three block evaluations per role. History is read from cache, not recomputed.
  Prefill, feedback generation, reset, empty/invalid input, abort and context limits
  are implemented. Position 511 can produce a byte but is never followed by an
  input at position 512. Mid-compute errors require reset before continuing.
- Dedicated browser Workers with immutable role selection, one-time verified
  loading, request validation/order, queue bounds and measured local durations.
  Phone 2 returns a byte/position by default; logits require explicit debug mode.
- Real little-endian activation payloads of 1,536 bytes. Separate Node worker
  runtimes and separate Chrome contexts reproduce the canonical predictions.
- Optional C++ scalar WASM and SIMD WASM matrix acceleration. These are compiled
  standalone modules without imports. Unsupported/missing kernels report reasons
  and fall back to scalar WASM or TypeScript. All other math remains TypeScript.

No Python, GPU APIs, fake logits, external inference services or trained model
substitutions participate in browser inference. The model is still intentionally
untrained and generates arbitrary byte sequences rather than reliable prose.

The 28 JS tests cover primitive math, exact GELU, causal/history behavior, KV

messages, injected compute failure, context overflow and fallback behavior.

Golden validation uses the existing seven cases: ASCII `Hello`, Hindi plus emoji,
accented UTF-8, arbitrary byte extremes, single zero/255, and maximum context. Each
backend processes **595 positions**, including autoregressive feedback. It checks
all **46 stored activation/logit samples** and all **49 expected generated bytes**.
The 512-byte fixture intentionally stores five sample vectors; this report does
not imply that a golden vector exists for every long-context position.

| Executed backend | Maximum activation error | Maximum logit error | Checked greedy IDs/generated sequences |
| --- | ---: | ---: | --- |
| TypeScript scalar | 1.847744e-6 | 1.668930e-6 | All match |
| C++ scalar WASM linear kernels | 1.847744e-6 | 1.668930e-6 | All match |
| C++ SIMD WASM linear kernels | 1.847744e-6 | 1.668930e-6 | All match |

The same maxima were measured in Chrome. Every value is checked using the original
`abs(actual-reference) <= 1e-4 + 1e-4 * abs(reference)` rule; tolerances were not
relaxed. Exact matrix-backend equality here is not a promise of universal
bit-for-bit equality between PyTorch, browsers, devices and future optimizations.

Isolated-worker validation gives each worker its own temporary directory containing
only its manifest and assigned shard; the other shard/full file is absent. Actual
ArrayBuffers are transferred and detach from the sender. Across the seven cases,
each role handles 595 requests and 1,785 layer evaluations; 913,920 activation
payload bytes cross the test boundary. No full-model helper or Python function is
called by either runtime.

## Measured desktop CPU performance

Environment: Node 24.6.0, macOS arm64. Fixed prompt `Hello`, 32 generated bytes,
temperature 0, unchanged model hashes, two warm-up runs and five measured runs per
backend. Each measured run includes reset, prefill and generation (36 processed
positions), using two local role engines. All measured output sequences match.

| Backend | Mean duration | Median duration | Generated bytes/s from mean duration |
| --- | ---: | ---: | ---: |
| TypeScript scalar | 341.14 ms | 340.19 ms | 93.80 |
| Scalar WASM linear kernels | 131.50 ms | 131.51 ms | 243.34 |
| SIMD WASM linear kernels | 84.60 ms | 84.57 ms | 378.23 |

These are **local desktop CPU measurements**, not mobile, WebRTC, or network
benchmarks. Raw samples include separate Phone 1/Phone 2 local compute durations.
No unrelated device clocks are compared and no network time is fabricated.

## Fixes made during validation

The first freestanding WASM link exposed an optimizer-generated `memset` import;
the build now uses freestanding/no-builtin flags and tests require zero imports.
The initial Chrome harness rejected `.worker.js` asset names; its allowlist was
corrected before the successful browser runs. The initial Playwright pin had a
reported vulnerability and was replaced with pinned 1.64.1; the final dependency
audit reported zero. These earlier failed attempts are not counted as successes.

## What remains incomplete

- The production versioned binary protocol, HELLO/READY handshake, network
  backpressure, peer timeouts and recovery belong to M3/M4. Current worker requests
  and raw activation payloads are groundwork, not the final network protocol.
- The browser harness uses a local automation driver between contexts; there is
  no WebRTC, STUN/TURN, signaling backend, or claimed physical P2P connection yet.
- iPhone Safari, Android Chrome and actual two-phone/offline tests have not run.
  Desktop Chrome success does not establish mobile compatibility/performance.
- WASM accelerates linear projections only. A complete C++ Transformer, optimized
  attention, batched prefill and memory/transport optimization remain optional
  follow-up work. SIMD adds role-local weight copies; mobile peak memory is unmeasured.
- UI integration, application state machine, QR signaling, cache persistence,
  offline readiness and static HTTPS deployment are later milestones.
- Concurrent generation sessions on one engine pair are unsupported; the caller
  must serialize them. Network interruption and browser suspension still need
  production transport tests. The local benchmark contains no communication costs.

The accepted M1 architecture, initialization, weights, parameter counts and golden
oracle were preserved. The full hackathon definition of done is still pending.
