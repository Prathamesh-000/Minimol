# Release gates: none may be skipped

| Gate | Owner | Proof required before merge |
|--|--|--|
| R0 | All | `01_FROZEN_CONTRACT.md` read and accepted; organizer model ambiguity explicitly acknowledged |
| R1 | Member 1 | `PYTHONPATH=ml pytest -q ml/test_reference.py`; exact param count, deterministic manifest, shard SHA256, causal mask checks |
| R2 | Member 2 | `cd web && npm test && npm run parity`; exact greedy byte outputs; cut/logit deviation within agreed tolerance |
| R3 | Member 3 | 2 actual phones; no TURN; QR exchange; exact 1,552-byte binary frame round-trip; LAN only candidate pair |
| R4 | All | `Hi` yields `[30,18,116]` in provisional canonical on **two phones**, blocks 0–2 / 3–5 computed on different devices |
| R5 | All | Long prompts, UTF-8, repeated runs, disconnect/reconnect, wrong shard checksum, >= 10 generated bytes tested |
| R6 | All | iOS Safari + Android Chrome, HTTPS page load, router WAN unplugged while LAN remains, no remote requests during inference |
| R7 | All | Throughput benchmark and stable repeatability; performance optimization does not change greedy byte outputs |

## Merge policy
- Use one branch per owner. Member 1 -> `feature/ml-reference`; Member 2 -> `feature/browser-engine`; Member 3 -> `feature/p2p-web`.
- Never directly commit or force push to `main` without review. Every PR includes a short test report, exactly which files changed, and any known exceptions.
- If fixture/model/contract changes, ALL members review and rerun R1–R4.
- Binary weights best distributed through static hosting or a release artifact; check source-control storage limits and use Git LFS only if team chooses to. The program must download only the role's shard at runtime.

## Known gaps in supplied starter code
- Organizer's canonical weight format and exact hidden architecture are not provided.
- No real iPhone + Android pair has yet been tested in the starter authoring environment.
- QR signaling for complex candidate SDP may exceed scannable single-code capacity.
- CPU kernels are a correct reference baseline, not an optimized judge-device benchmark.
- Failure/reconnect paths and long-context golden fixture set need more coverage.
- Full Vite build requires installing npm dependencies on a network-enabled development environment.
