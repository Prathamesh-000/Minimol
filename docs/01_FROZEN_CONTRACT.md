# Shared integration contract v1 — Do not diverge

These are team-defined interfaces, not claimed to be organizer-supplied.

## Model
- `V=256`, `T<=512`, `N=6`, `D=384`, `H=6`, `headDim=64`, `FF=1536`, `parameters=11,040,768` (44,163,072 FP32 bytes).
- Our **provisional** exact count corresponds to learned byte/position embeddings, 6 pre-LN Transformer blocks, affine norms, qkv & MLP biases, GELU approximate=`tanh`, affine final norm, an untied bias-free output head. Uses PyTorch constructor order as documented in `ml/model.py`, `manual_seed(42)` prior to constructing model.
- Architecture ambiguities must be resolved with organizers if they provide an official oracle. Never call arbitrary seed-42 weights universally deterministic across independently defined implementations.
- PyTorch module names are the canonical tensor keys, `named_parameters()` order canonical for full `weights.bin`, tensor rows output-major for `nn.Linear`. All exported numbers FP32 little endian, no quantization.

## Weights/manifest
`python ml/export_weights.py` writes the full `ml/artifacts/weights.bin`, `web/public/model/phone1.bin`, `phone2.bin`, `manifest.json`, `fixtures.json`.
Phone 1 shard = 5,618,304 FP32 params (22,473,216 bytes), Phone 2 = 5,422,464 params (21,689,856 bytes). Each role loads only its own shard, verifying SHA-256 and byte lengths. Never download the other shard or full weights in app.
Manifest schemaVersion 1; contains fullWeight SHA, shard SHA, `{name,role,shape,byteOffset,byteLength,dtype,byteOrder}` per tensor. No tensor names/shape/offset mutations without everyone agreeing.

## Engine API (Member 2)
```js
const {engine, modelId} = await createEngine({role: 'phone1'|'phone2', manifestUrl:'/model/manifest.json'});
engine.reset();
const cut = await engine.forwardByte({token: 72, position:0});
// Returns Float32Array(384) on phone1 only.
const result = await engine.forwardActivation({activation:cut, position:0, sample:true});
// Returns {byte: integer 0..255, logits: Float32Array(256)} on phone2 only.
// With sample:false, returns {byte:null} and must still update caches.
engine.dispose();
```
Each engine's accepted positions consecutive, start 0, stop at 511. Both caches cleared on RUN_START. Member 2 does NOT edit app or WebRTC source.

## WebRTC (Member 3)
`new RTCPeerConnection({iceServers:[]})` (no STUN/TURN). Reliable, ordered DataChannel with `binaryType='arraybuffer'`. Signaling is out-of-band (QR or manual copy); after pairing, ALL inference payloads over DataChannel only. Both phones must retain LAN connectivity.

Control JSON strings (all include `version:1`):
- `HELLO {role,modelId}`; fail on mismatched hash or same roles.
- `RUN_START {runId,runSequence,promptByteLength,maxNewBytes}`; B resets then replies `READY {runId}`.
- `STEP_DONE {runId,position}` for prefill with `sample:false`.
- `BYTE {runId,position,value}` for sample with `sample:true`.
- `END {runId}`; `ERROR {runId,reason}` to abort.

Activation binary frame **exactly 1,552 bytes**:
| Offset | Binary type | Meaning |
|--|--|--|
| 0 | uint8 | version = 1 |
| 1 | uint8 | type = 1 (ACTIVATION) |
| 2 | uint8 | sample = 0/1 |
| 3 | uint8 | reserved = 0 |
| 4 | uint32 little endian | position (0..511) |
| 8 | uint32 little endian | runSequence (positive) |
| 12 | uint32 little endian | floatCount = 384 |
| 16..1551 | 384 x FP32 little endian | 384-dimensional cut activation |

Reject extra/short frames, NaNs, stale runSequence, unexpected positions, invalid bytes, wrong protocol version. Exactly one activation in flight and A waits for `STEP_DONE` or `BYTE` before sending another.

## Generation loop (Member 3)
Prompt `TextEncoder.encode` gives UTF-8 bytes `0..255`; do not use JS character positions. Empty prompt/length >512 rejected. For `n` prompt bytes, process position `0..n-2` with sample=false, position `n-1` with sample=true -> generated byte #1. Then process that byte as input at position `n`, sample=true -> generated byte #2, etc. Stop at position 511. Maximum new bytes is `min(userLimit,513-n)`. Display both best-effort decoded UTF-8 and exact hex output; random model will generate mostly arbitrary bytes. No artificial BOS token. End/abort resets state before next RUN_START.

## Correctness versus performance
First verify Python/JS cut activations & 256 logits within tolerance, then exact greedy bytes for multiple contexts; cache must match full causal recomputation. Only afterward optimize via workers/WASM. No WebGPU, WebGL compute, backend compute, relay, native app or external inference API.
