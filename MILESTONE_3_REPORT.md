## Two-process execution proof

The recorded run used Node process IDs **34505** and **34512**, distinct from
each other and the parent test process. Each child independently loads and hashes
its own shard. Its directory contains exactly its assigned binary and manifest.
Runtime A possesses 5,618,304 parameters (embeddings/layers 0–2); Runtime B
possesses 5,422,464 (layers 3–5/final norm/head). Owned tensor-name lists are
disjoint and together cover the 77 expected tensors. No child constructs the
full PyTorch model, loads the other shard or executes all six layers.

The coordinator runs inside process A. A parent development broker forwards
opaque binary frames between the children and implements test-only fault injection.
Neither the broker nor process A computes process B's output. This is a local
distributed simulation; no activation server is part of the production library.

Across seven canonical prompts, **595 positions per runtime** were processed.
Each role executed **1,785 layer evaluations**, three per position. The tests
check every step's request ID, position, assigned layer IDs, cache lengths before
and after, and matching activation/response frames. Every activation frame is
1,576 bytes: 40 header bytes and exactly 384 FP32 values / 1,536 payload bytes.
Normal predictions return a byte and local duration, with no logits. The golden
simulation explicitly negotiates debug logits to compare numerical outputs.

The cases cover ASCII, Hindi/emoji UTF-8, accented UTF-8, arbitrary bytes, single
byte prompts and all 512 context positions. All **49 expected generated bytes**
match. At the **46 stored golden vector positions**, maximum errors were:

| Value | Maximum absolute error |
| --- | ---: |
| Phone 1 activation | 1.847744e-6 |
| Final logits | 1.668930e-6 |

Every checked greedy byte matches. The original `atol=1e-4, rtol=1e-4` rule is
unchanged. Sparse long-context samples are not claimed as golden vectors for all
512 positions. Per-step traces, process identities, tensor inventories and all
1,208 exchanged frame headers are in
[the process evidence JSON](artifacts/reports/milestone3-processes.json).

## Failure and lifecycle behavior

Executed tests reject malformed headers/payloads, nonfinite floats, unknown
versions/types/flags, unsafe sizes, incompatible roles/configuration/model/shard
hashes/dimensions, stale or mismatched response IDs/positions/generations/connection
identities, duplicates, and unnegotiated logits. They verify acknowledged cache
reset/stop and repeated generation, local cancellation, fresh-connection recovery,
bounded backpressure, ordering, timeout and send-error cleanup.

Separate-process tests deliberately drop NEXT_BYTE: the pending request times
out, both caches clear, and the activation is sent exactly once. Killing Runtime
B while an activation is pending rejects generation and clears A's cache. A
modified HELLO configuration hash rejects the handshake before inference.

Failures invalidate the connection rather than silently resuming uncertain KV
state. The sender bounds its queue at 32 frames / 64 KiB with a 16 KiB high-water
mark and deadlines. Receiver queues are bounded at eight frames / 16 KiB. A lost
or stalled activation is never silently discarded/retried as successful work.

## Remaining limits

This milestone proves execution in separate OS processes with distinct heaps and
role-only loading. It does not provide an OS filesystem security sandbox: trusted
processes run under the same user account. No physical phone, direct ICE path,
WebRTC DataChannel, QR signaling, offline application or mobile benchmark is
claimed. The current protocol is transport-neutral; M4 must supply a reliable
ordered DataChannel adapter and connectivity/signaling validation.

The protocol permits one inference request in flight. Batched prefill, automatic
resume and retransmission are deliberately unsupported. Interruptions require a
fresh connection. Debug logits are optional diagnostic traffic, not normal
prediction payloads. SHA-256 metadata validates model compatibility and integrity,
not human identity. Best-effort ERROR frames can be lost during connection closure.

No distributed performance benchmark is claimed from test-suite wall times.
The model remains the same untrained seed-42 Transformer. The full hackathon
definition of done remains pending, beginning with Milestone 4 after this verified
simulation.
